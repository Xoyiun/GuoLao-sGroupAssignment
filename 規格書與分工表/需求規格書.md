Use Case
UC-01 (Add New Course): Admin inputs course ID, name, credits, slots, and room → System validates no duplicate ID and positive credits → System saves course. 
UC-02 (Query Courses): Admin/Student searches by Teacher, Day, Course Type or Remaining Capacity → System outputs matching course list.
UC-03 (Modify/Delete Data): Admin updates course or student details → System verifies no active student enrollments exist before deleting a course → System updates/deletes record.

Core Validation Rules
Unique IDs: Course IDs (course_id) and Student IDs (student_id) must be strictly unique.
Valid Credits & Capacity: Course credits must be positive integers (credits > 0), and course/classroom capacity must be at least 1 (capacity >= 1).
Time Slot Rules: Days are numbered 1–7 (Mon–Sun). Periods are 1–9, a, b, c. Time slots are represented as strings (e.g., "1-4", "2-a").
Deletion Constraint: A course cannot be deleted if any student is currently enrolled in it, unless the student drops the course first.
Multi-Criteria Search: Query functions must filter by Course ID, Teacher, Day, Course Type, and Remaining Capacity.

Requirements Specification v1 (⁠需求規格 v1⁠)
System Overview: A CLI-based course selection and scheduling system written in Python.  
 Functional Requirements (F1–F11):
 F1 Data Management: Add/Edit/Delete/Search courses, students, and classrooms.  
 F2 Conflict Checking: Detect schedule, room, event, and credit limit conflicts simultaneously.  
 F3 Timetable Display: Generate a 2D weekly schedule grid and find consecutive free time slots.  
 F4 Campus Events: Book non-course events and allocate available rooms.  
 F5 Course Filtering: Filter courses based on user preferences and constraints.  
 F6 Data Persistence: Load/save data to CSV/JSON format safely.  
 F7–F8 Optimization & Search: Search best timetables using Brute-Force and Backtracking algorithms.  
 F9 Path Planning: Calculate campus walking times using BFS/Dijkstra.  
 F10 Dynamic Replanning: Re-adjust schedules when classes are canceled or changed.  
 F11 AI Collaboration: Use AI for code review, refactoring, and testing verification.  
 Non-Functional Requirements: Modular design, strict absence of global variables, automated test coverage, and Git version control.
