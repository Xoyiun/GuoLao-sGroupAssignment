## 二、本迭代完成內容

### 1. 建立 GitHub Actions 測試流程（11/22）

新增 [`.github/workflows/test.yml`](../../.github/workflows/test.yml)，在 push
與 pull request 時自動執行測試。流程包含：

- 使用 `actions/checkout@v7` 取出專案。
- 使用 `astral-sh/setup-uv@v7` 設定 Python 3.14 與 uv 快取。
- 以 `uv sync --locked` 安裝鎖定的依賴。
- 執行 `uv run python TestDriver.py --junitxml=test-results.xml`。
- 即使測試失敗，也繼續產生報告並上傳結果，方便除錯。

### 2. 新增測試報告與測試摘要（11/22–11/23）

配合 [TestDriver/make_report.py](../../TestDriver/make_report.py) 的報告產生
功能，CI 會依 `TestDriver/test_*.py` 執行各測試模組與 CLI 測試，將結果轉換為 HTML 報告。
每份報告包含測試數量、通過率、核心測試進度、測試說明及失敗訊息。

另外在 GitHub Actions 的 Summary 中加入：

- 整體測試狀態。
- 測試案例總數。
- 通過、失敗與略過數量。
- 各測試模組的分項統計。
- 完整 XML 與 HTML 報告的下載連結。

測試結果以 XML 為統計來源，避免只依賴終端機輸出或人工計算。

### 3. 更新專案使用文件（11/22）

更新 [README.md](../../README.md)，補充：

- push 或建立 pull request 時會自動執行 CI。
- GitHub Actions Summary 的查看方式。
- Artifacts 中 XML 與 HTML 測試報告的下載方式。
- `TestDriver.py` 的完整測試與指定標記測試指令。

### 4. 影片 I 與團隊資源整合（11/9–11/22）

## 五、Code Review 與協作紀錄

1. 以 pull request 與 merge 流程整合團隊分支，確認整合後的測試仍可執行。
2. 在 CI 工作流程中使用 `if: always()` 產生報告與上傳 Artifacts，避免測試
   失敗時失去除錯資料。
3. 以 JUnit XML 作為統計來源，分別檢查完整測試與各功能模組測試結果。
4. 處理影片 I Kdenlive 專案的合併衝突，確認媒體資源與專案設定一致。

### 程式理解：`TestDriver.py` 與 CI 報告流程

- **Input：** `TestDriver.py` 接收 pytest 參數；GitHub Actions 傳入
  `--junitxml=test-results.xml`，報告流程逐一讀取 `TestDriver/test_*.py`。
- **Process：** `TestDriver.main` 將參數交給 pytest；CI 先執行完整回歸測試，
  再對各測試檔產生 JUnit XML，最後由 `make_report.py` 解析 XML 並產生 HTML。
- **Output：** 完整測試結果、各模組 HTML 報告及 GitHub Actions Summary。
- **Boundary／Error：** 測試失敗時，報告與上傳步驟仍以 `if: always()` 執行；
  若缺少 XML，Summary 會顯示未產生測試結果，而不是偽造通過數字。

## 六、遇到的問題與改善方式

### 遇到的問題

1. 僅有終端機測試輸出時，GitHub Actions 頁面不容易快速確認各模組的結果。
2. 測試失敗時若直接停止工作流程，會無法取得完整的失敗報告。
3. Kdenlive 專案檔在不同分支修改後產生 producer 與 chain 設定衝突。

### 改善方式

1. 將測試結果輸出為 JUnit XML，並產生分模組 HTML 報告。
2. 將報告與摘要步驟設為失敗後仍執行，保留測試診斷資料。
3. 合併後檢查媒體路徑、播放時長與專案設定，確認影片專案可以繼續編輯。

### TDD／驗證紀錄：F9 BFS（11/23）

1. **Requirement：** F9 路徑模組的 `FindShortestPath` 除 Dijkstra 外，應支援
   BFS，並回傳可驗證的節點路徑。
2. **Test：** 新增 `test_bfs_is_supported`，以 A→C 的圖形驗證 BFS 回傳
   `["A", "C"]`，並保留 Dijkstra 加權最短路徑測試。
3. **Red：** 基準版本雖在介面文件中列出 `bfs`，實際只執行 Dijkstra，
   因此 BFS 測試無法得到預期結果。
4. **Green：** 在 `CampusPath.py` 補上 BFS 分支後，F9 測試通過。
5. **Refactor：** 保留 Dijkstra 與 BFS 共用的節點驗證、路徑重建及錯誤回傳介面，
   避免改變既有呼叫端行為。
6. **Regression Test：** 執行 `uv run python TestDriver.py`，結果為
   **196 passed、0 failed、0 skipped**。
