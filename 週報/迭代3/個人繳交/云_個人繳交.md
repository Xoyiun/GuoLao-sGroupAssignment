## 二、本迭代完成內容

### 1. 建立 GitHub Actions 測試流程

新增 [`.github/workflows/test.yml`](../../.github/workflows/test.yml)，在 push
與 pull request 時自動執行測試。流程包含：

- 使用 `actions/checkout@v7` 取出專案。
- 使用 `astral-sh/setup-uv@v7` 設定 Python 3.14 與 uv 快取。
- 以 `uv sync --locked` 安裝鎖定的依賴。
- 執行 `uv run python TestDriver.py --junitxml=test-results.xml`。
- 即使測試失敗，也繼續產生報告並上傳結果，方便除錯。

### 2. 新增測試報告與測試摘要

配合 [TestDriver/make_report.py](../../TestDriver/make_report.py) 的報告產生
功能，CI 會分別執行 F1、F2、F3、F4 與 CLI 測試，將結果轉換為 HTML 報告。
每份報告包含測試數量、通過率、核心測試進度、測試說明及失敗訊息。

另外在 GitHub Actions 的 Summary 中加入：

- 整體測試狀態。
- 測試案例總數。
- 通過、失敗與略過數量。
- 各測試模組的分項統計。
- 完整 XML 與 HTML 報告的下載連結。

測試結果以 XML 為統計來源，避免只依賴終端機輸出或人工計算。

### 3. 更新專案使用文件

更新 [README.md](../../README.md)，補充：

- push 或建立 pull request 時會自動執行 CI。
- GitHub Actions Summary 的查看方式。
- Artifacts 中 XML 與 HTML 測試報告的下載方式。
- `TestDriver.py` 的完整測試與指定標記測試指令。

### 4. 影片 I 與團隊資源整合

協助整合影片 I 所需的音檔、影片、逐字稿、投影片與 Kdenlive 專案檔，
並處理合併 Kdenlive 專案時的 producer、chain 設定衝突，使影片專案中的
媒體路徑與播放設定保持一致。同時配合團隊修改影片投影片及逐字稿中的
講者順序與版面內容。

## 六、遇到的問題與改善方式

### 遇到的問題

1. 僅有終端機測試輸出時，GitHub Actions 頁面不容易快速確認各模組的結果。
2. 測試失敗時若直接停止工作流程，會無法取得完整的失敗報告。
3. Kdenlive 專案檔在不同分支修改後產生 producer 與 chain 設定衝突。

### 改善方式

1. 將測試結果輸出為 JUnit XML，並產生分模組 HTML 報告。
2. 將報告與摘要步驟設為失敗後仍執行，保留測試診斷資料。
3. 合併後檢查媒體路徑、播放時長與專案設定，確認影片專案可以繼續編輯。
