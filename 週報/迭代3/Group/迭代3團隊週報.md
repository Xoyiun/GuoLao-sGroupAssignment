## 5 軟體測試（Software Testing and Verification）

### 5.1 測試案例設計（Test case design）

測試範圍為 Iteration 3 整合版的 F1～F6，包含正常、邊界、錯誤與衝突案例。
F4 另有 20 項專項測試。所有測試使用獨立測試資料或測試副本，
不直接修改正式 `UserData`，讓測試可以重複執行。

#### 正常案例

| 編號 | 功能 | 測試情境與輸入 | 預期結果 |
| :--- | :--- | :--- | :--- |

| TC02 | F1 | 新增學生並以學號查詢。 | 查到新增學生，且只有一筆資料。 |
| TC03 | F2 | 學生加選有名額且無衝突的課程。 | 加選成功，學生清單與課程人數同步更新。 |
| TC04 | F3 | 建立 7×12 課表並查詢課程格位。 | 每個時段正確顯示課程或活動。 |
| TC05 | F4 | 新增活動，容量、設備與時段均符合。 | 找到可用教室並建立活動。 |
| TC06 | F6 | 儲存課程、學生、教室及選課資料後重新載入。 | 資料欄位與關聯維持一致。 |
| TC07 | CLI | 執行新增、查詢、加選、退選及課表流程。 | CLI 操作成功且輸出符合規格。 |

#### 邊界案例

| 編號 | 功能 | 測試情境與輸入 | 預期結果 |
| :--- | :--- | :--- | :--- |

| TC09 | F2 | 加選後學分剛好等於上限。 | 加選成功，總學分等於上限。 |
| TC10 | F2 | 依序加選只剩最後一個名額的課程。 | 最後一個名額可成功加選，後續加選被拒絕。 |

| TC13 | F4 | 活動容量等於教室容量。 | 活動可建立，達容量上限後拒絕新增報名。 |

| TC15 | F6 | 儲存空的課程、學生及教室集合。 | 可成功載入空集合。 |
