## 一、作業規範摘要

1. 窮舉搜尋：產生所有候選課程組合，逐一檢查限制條件。
2. 回溯搜尋：在搜尋過程中及早排除違反限制的組合。
3. 記錄兩種演算法的搜尋節點數、執行時間及可行解數量。
4. 驗證兩種方法對相同輸入是否產生一致的可行解集合。
5. 比較不同候選課程數量對執行時間的影響。
6. 驗收：至少設計候選課程數量為 8、12、16 門的三組測試資料；若窮舉法執行時間過長，須設定合理的時間上限，並如實記錄未完成情況。

## 二、迭代 4 版本的問題

| 項目 | 問題 | 本迭代處理 |
| :--- | :--- | :--- |
| 回溯法 | 只是把每個「選／不選」都走一遍，沒有任何剪枝，節點數（2ⁿ⁺¹ − 1）比窮舉法（2ⁿ）還多 | 依限制條件在搜尋途中剪枝 |
| 可行解 | 只呼叫判斷函式，不收集結果，無法驗證兩法一致、也沒有可行解數量 | 兩法都回傳完整的可行解集合 |
| 限制條件 | F8 自己另寫一份，沒有檢查與已選課程的衝堂，與 F7 不一致 | F7、F8 共用同一份條件（`BuildSearchProblem`、`IsFeasibleSelection`） |
| 時間上限 | 沒有 | 可設定上限，逾時回報「未完成」並保留已搜尋的節點數 |
| 實驗 | 沒有 8、12、16 門的資料 | 新增三組（另加 20 門）測試資料與實驗紀錄 |

## 三、搜尋問題的定義（與 F7 相同）

輸入與 F7 的 `preferences` 相同：必修課、候選選修課、最低／最高學分、不可上課時段。學生已選的課視為已排好的課。

一個「選法」是候選課程的子集合，與必修課合起來成為方案。方案可行的條件：

| 編號 | 條件 | 可否在搜尋途中檢查 |
| :--- | :--- | :--- |
| C1 | 總學分 ≤ 最高學分 | 可：再加課只會更多 |
| C2 | 方案內的課彼此不衝堂，也不與已選課程衝堂 | 可：衝堂不會因為多加課而消失 |
| C3 | 不排在不可上課時段 | 可：只看新加入的那門課 |
| C4 | 不選額滿課程 | 可：只看新加入的那門課 |
| C5 | 總學分 ≥ 最低學分 | 只能在最後確認，但可用「目前學分＋剩下所有候選的學分」估計，達不到就提早放棄 |

## 四、演算法

設候選課程有 n 門。

### 4.1 窮舉法 `BruteForceSearch`

```text
for 每個子集合 S（從 0 到 2ⁿ − 1 的位元遮罩）:
    節點數 += 1
    if 必修課 ∪ S 符合 C1～C5:
        記錄為可行解
```

* 節點：每檢查一個子集合算一個節點，共 2ⁿ 個。
* 時間複雜度：O(2ⁿ × n²)（每個子集合要做兩兩衝堂比對）。
* 優點：簡單、一定找得到所有解；缺點：不論限制多嚴格，都要檢查全部子集合。

### 4.2 回溯法 `BacktrackingSearch`

```text
visit(第 i 門候選, 目前的選法, 目前學分):
    節點數 += 1
    if 目前學分 + 剩下候選的學分總和 < 最低學分: return      ← C5 剪枝
    if i == n:
        記錄為可行解; return
    visit(i + 1, 目前的選法, 目前學分)                          ← 不選第 i 門
    if 第 i 門加入後仍符合 C1～C4:                               ← C1～C4 剪枝
        visit(i + 1, 目前的選法 + 第 i 門, 目前學分 + 學分)      ← 選第 i 門
```

* 節點：每呼叫一次 `visit` 算一個節點。
* 剪枝：違反 C1～C4 的分支不再往下走；C5 用剩餘學分估計，確定達不到最低學分就停止。
* 最壞情況（沒有任何限制）仍要走 2ⁿ⁺¹ − 1 個節點，但限制越多、剪掉的分支越多。

### 4.3 節點數不能直接比大小

兩種方法的「節點」意義不同：窮舉法只算完整的子集合（2ⁿ 個），回溯法連中途的部分選法也算（最多 2ⁿ⁺¹ − 1 個）。限制不夠多時，回溯法多出的中途節點會抵銷剪枝省下的部分。

* 測試 S03 的小題目（4 門）：回溯法 22 個節點，窮舉法 16 個。
* 效能實驗 8 門：回溯法 279 個，窮舉法 256 個。
* 12 門以上，剪枝的效果才明顯超過中途節點（見效能實驗）。

### 4.4 一致性驗證

兩法各自回傳可行解集合（每個解以排序後的課程代號表示）。`CompareAlgorithms` 比較兩個集合是否完全相同；任一方因時間上限未完成時，一致性標為「無法判定」，不當作一致。

### 4.5 時間上限

兩法都接受 `timeLimit`（秒）。每走一個節點檢查一次是否逾時；逾時就停止，回傳 `completed = False` 與目前的節點數、已找到的解數。實驗中把窮舉法逾時如實記錄為「未完成」。

## 五、輸出

（以下數字僅示意格式，實際數據見效能實驗）

```text
CompareAlgorithms(database, studentId, preferences, timeLimit=None) →
(True, OK, {
  "brute_force":  {"nodes": 4096, "seconds": 0.0213, "solutions": 37, "completed": True},
  "backtracking": {"nodes":  611, "seconds": 0.0031, "solutions": 37, "completed": True},
  "consistent": True,          # 兩法都完成且可行解集合相同；有一方未完成時為 None
  "candidate_count": 12,
})
```

格式錯誤（學生或必修課不存在、欄位型別錯誤）回傳 `(False, INVALID_FIELD, {})`。

## 六、驗收測試規劃（先寫測試，再實作）

| 編號 | 測試 | 驗證內容 |
| :--- | :--- | :--- |
| S01 | `test_BruteForceFindsEveryFeasibleSelection` | 手算的小題目：窮舉法找到全部可行解，節點數 = 2ⁿ |
| S02 | `test_BruteForceRespectsAllConstraints` | 衝堂、已選課衝堂、禁止時段、額滿、學分上下限都會排除 |
| S03 | `test_BacktrackingMatchesBruteForce` | 同一題目兩法的可行解集合相同 |
| S04 | `test_BacktrackingPrunes` | 有限制時回溯法節點數少於窮舉法，並等於手算值 |
| S05 | `test_TimeLimitStopsAndReportsIncomplete` | 時間上限為 0 時回報未完成，一致性為 `None` |
| S06 | `test_CompareReportsBothAlgorithms` | 比較報告含節點數、時間、解數與一致性 |
| S07 | `test_F7AndF8AgreeOnFeasiblePlans` | F8 的可行解集合與 F7 搜尋結果相同 |
| S08 | `test_ExperimentDatasetsAgree`（8、12、16 門） | 三組資料存在且兩法結果一致；12 門以上回溯法節點較少（8 門不成立，見 4.3） |
| S10 | `test_RunExperimentSummarizesRepeatedRuns` | 實驗函式重複執行並回傳時間中位數 |
| S09 | `test_CompareRejectsInvalidInput` | 學生或必修課不存在回報 `INVALID_FIELD` |
