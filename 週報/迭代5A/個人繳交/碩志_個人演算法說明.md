## 二、個人演算法說明

### 2.1 問題

給定必修課、n 門候選選修課、學分上下限、不可上課時段，找出所有「必修＋部分候選」的可行組合：不衝堂（含已選的課）、學分在範圍內、不選額滿課、不排禁止時段。

### 2.2 窮舉法

把每個子集合對應到一個 n 位元的數字（第 i 位是 1 代表選第 i 門），從 0 數到 2ⁿ − 1，逐一用 `IsFeasibleSelection` 檢查。

* 節點數固定 2ⁿ，與限制多寡無關。
* 每個子集合要兩兩比對衝堂，時間 O(2ⁿ × n²)。

### 2.3 回溯法

把搜尋看成一棵二元樹：第 i 層決定第 i 門「不選」或「選」。

```text
Visit(i, 目前選法, 目前學分):
    節點數 += 1
    若 目前學分 + 第 i 門之後所有候選學分 < 最低學分：放棄這個分支
    若 i == n：記錄可行解，返回
    Visit(i + 1, 目前選法, 目前學分)                       # 不選
    若 加入第 i 門後仍不超過學分上限、不衝堂、不在禁止時段、不額滿：
        Visit(i + 1, 目前選法 + 第 i 門, 目前學分 + 學分)  # 選
```

**為什麼可以提早剪枝：** 學分上限、衝堂、禁止時段、額滿這四個條件有「單調性」：一個選法一旦違反，再多加任何課都還是違反，所以整個分支都不必再走。最低學分則反過來：用「剩下的全部選上」估計最多能拿到幾學分，連這樣都不夠，就不可能達到。

**剩餘學分的計算：** 事先算好 `suffix[i]` = 第 i 門之後所有候選的學分總和，每個節點只要 O(1) 就能判斷。

### 2.4 兩者的比較

| 項目 | 窮舉法 | 回溯法 |
| :--- | :--- | :--- |
| 節點定義 | 完整的子集合 | 走訪過的部分選法（含中途節點） |
| 節點數上限 | 2ⁿ | 2ⁿ⁺¹ − 1 |
| 限制少時 | 2ⁿ | 可能比窮舉法多（8 門：279 > 256） |
| 限制多時 | 仍是 2ⁿ | 大幅減少（20 門：24,089 vs 1,048,576） |
| 結果 | 全部可行解 | 全部可行解（實驗中完全一致） |

2. **小題目驗證正確性，大題目驗證趨勢**：S01–S04 用 4、5、8 門的小題目，答案可以人工核對；S08 用 8、12、16 門驗證一致性與剪枝效果。

## 四、程式理解說明：`BacktrackingSearch(problem, timeLimit=None)`

* **Input：** `BuildSearchProblem` 產生的搜尋問題（必修、候選、已選課程、學分上下限、禁止時段），以及時間上限（秒，可省略）。
* **Process：** 先把必修課逐一加入，必修課本身就違反條件時直接結束；再從第 0 門候選開始遞迴，先走「不選」再走「選」；每個節點先檢查是否逾時，再用剩餘學分判斷能否達到最低學分；到最後一層時用 F7 的完整條件再確認一次並記錄。
* **Output：** `{"solutions": 排序後的可行解, "nodes": 走訪節點數, "seconds": 執行時間, "completed": 是否完成}`。
* **Boundary / Error Case：**
  * 沒有候選課程時只走訪根節點，必修課符合條件就是唯一的解。
  * 時間上限為 0 時一個節點都不走，`completed` 為 False。
  * 最低學分為 0 時不會因學分剪枝，空選法也是可行解。

## 八、心得

這次最大的體會是「演算法比較不能只看快慢」。回溯法在小題目時並沒有比較好，要靠限制條件夠多、候選夠多，剪枝才會贏。如果沒有先手算節點數、把期望值寫進測試，我們很可能只會看到「回溯法比較快」的結論，而忽略了節點定義本身就不同。
