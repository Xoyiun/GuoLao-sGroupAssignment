# 個人工作紀錄 (Iteration 0 / 第 5 週)

## 一、個人角色與負責工作說明
* **團隊角色**：成員 C（需求分析與資料管理負責人 / 副組長）
* **主要負責工作**：
  1. 使用者需求規格 與 Use Case 初版設計。
  2. 設計系統基礎資料模型（Schema），定義課程、學生、教室、活動與校園地圖之資料結構 。
  3. 建立並維護專案初始資料庫檔案 `04_data_format.json`，實作 F6 資料儲存與容錯載入機制 。
  4. 撰寫 `data_manager.py` 模組，封裝 `DataManager` 類別，提供統一且封裝良好的資料存取介面 (API) 供全組成員使用。

---

## 二、本週工作內容
1. **初始資料庫架構設計與產出 (`04_data_format.json`)**：
   * 設計並生成涵蓋 20 門課程、15 名學生、5 間教室、3 項校園活動，以及包含 10 個建築物節點與 15 條步行路線之 `campus_graph` 資料庫 。
   * 預置測試邊界資料（例如：額滿課程 `GE101`、0 學分體育課 `PE101`、多種跨系學生選課組合），利於後續 F2 衝堂檢查與 F5 條件篩選之自動化測試 。
2. **資料管理模組開發 (`data_manager.py`)**：
   * 使用物件導向程式設計 (OOP) 實作 `DataManager` 類別，嚴格遵循無全域變數規範 。
   * 實作 JSON 讀取與容錯處理機制（捕捉 `FileNotFoundError` 與 `JSONDecodeError`），防止單一筆資料損毀導致系統異常終止。
   * 提供 `get_courses()`、`get_students()`、`get_classrooms()`、`get_activities()` 及 `get_campus_graph()` 等 Getter 方法，並設計記憶體資料更新與 `save()` 寫回硬碟機制 。
   * 採用單例模式（Singleton）技巧，在檔末建立預設實體 `data_manager = DataManager()`，讓隊友可直接透過 `from data_manager import data_manager` 引用。
3. **開發規範與環境對齊**：
   * 確認全案開發環境（Anaconda / VS Code）之執行相容性。
   * 確立「檔案與資料夾路徑不包含中文」、「核心函式採無 `input()` 依賴設計」等 Coding Convention 。

## 三、本週工作成果
1. **交付檔案與資料結構**：
   * 產出標準 JSON 格式檔案 **`04_data_format.json`**（已發布並納入版控）。
   * 產出 Python 模組 **`data_manager.py`**，提供全組一致的資料存取介面。
2. **Git Commit 提交紀錄** [9]：
   * `新增 Iteration 0 初始資料庫檔 04_data_format.json`
   * `實作 DataManager 類別與單例模式資料載入器 (data_manager.py)`
3. **程式理解說明（核心函式）** [9]：
   * **函式名稱**：`DataManager._load_data(self)`
   * **Input**：`self.json_path`（預設為 `"04_data_format.json"`）。
   * **Process**：檢查檔案是否存在；若存在則以 `utf-8` 編碼開啟並呼叫 `json.load()` 解析為 Python 字典；若發生格式錯誤則捕捉例外並初始化預設資料結構。
   * **Output**：包含 `courses`、`students`、`classrooms`、`activities` 與 `campus_graph` 的字典物件。
   * **Boundary / Error Case**：檔案不存在時警示並回傳空結構；JSON 格式損毀 (`JSONDecodeError`) 時捕捉例外避免系統崩潰，符合 F6 容錯載入規範 [1]。
4. **AI 協作紀錄與驗證** [4, 9]：
   * **提問情境 / Prompt**：請教 AI 如何將 JSON 檔案讀寫封裝為 Class，並實現無全域變數且讓組員便利 `import` 的架構。
   * **AI 建議摘要**：建議使用 OOP 封裝 `DataManager` 類別，在檔案末端創立單例物件，並指出僅有 `data_manager.py` 需 `import json`，其他模組無需直接處理 JSON 解析。
   * **採納情形**：[採納] 完全符合作業規範中「禁用全域變數」與「模組獨立性」之規定 [4]。
   * **驗證方式**：撰寫測試程式進行資料讀取與寫入測試，確認 `get_courses()` 能正確回傳 20 門課程資料，呼叫 `save()` 後 JSON 寫回格式正確（`indent=2`，無中文亂碼）。

## 四、工作心得與後續規劃
* **工作心得**：
  在 Iteration 0 階段，建立穩定且好用的資料中樞（Data Hub）是整體專案順利推進的關鍵。透過將複雜的 `json.load()` 與 `json.dump()` 封裝在 `DataManager` 類別內，其他隊友在開發 F2 衝堂檢查、F3 課表矩陣或 F9 地圖路徑時，就不需關心底層檔案讀寫細節，大幅降低了跨模組整合的難度。同時我也體會到遵從「不使用全域變數」與「嚴格路徑命名」對團隊協作的重要性 。
