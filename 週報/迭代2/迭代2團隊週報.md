## 一、可執行版本

本迭代的程式位於 [`CampusPlanner/Code/`](../../CampusPlanner/Code/)，資料位於
[`CampusPlanner/UserData/`](../../CampusPlanner/UserData/)。

在專案根目錄執行：

```powershell
uv run python CampusPlanner/Code/Main.py
uv run python TestDriver.py
```

### 目前模組分工

| 模組 | 檔案 | 對應功能 |
| :--- | :--- | :--- |
| 命令列介面 | `Main.py` | 選單、輸入解析與結果顯示 |
| 資料管理 | `CourseDataManager.py` | F1 課程、學生與教室資料的新增、修改、刪除、查詢 |
| 資料存取 | `StorageManager.py` | F6 依 ID 分檔讀寫與損毀檔案容錯載入 |
| 衝堂與選課 | `ConflictChecker.py` | F2 衝堂檢查、加選、退選 |
| 課表與空閒時段 | `Timetable.py` | F3 |
| 活動與教室配置 | `VenueManager.py` | F4（初版） |
| 共用定義 | `Constants.py`、`TimeSlotUtils.py` | 錯誤碼、規格常數與時段比對 |

### 命令列選單（v2）

| 選項 | 功能 | 對應 |
| :--- | :--- | :--- |
| 1–11 | 課程、學生、教室的新增、修改、刪除、查詢 | F1 |
| 12 | 查看個人課表（7×12 矩陣、每日節數、總學分、空堂數、課程／活動圖例） | F3 |
| 13 | 依星期、節次、課程代號查詢個人課表 | F3 |
| 14 | 查詢連續空堂（可跨日） | F3 |
| 15 | 加選課程／報名活動（一次列出所有衝突） | F2 |
| 16 | 退選課程／取消報名 | F2 |

F2 加選失敗時的輸出（依作業規範 F2 的輸出範例）：

```text
學生：S10902 林美玲

選課結果：失敗
衝突 1：星期四第 2、3 節
已選課程：CS102 資料結構
衝突 2：課程已額滿
人數上限：1，目前人數：1
目前學分：7
加選後學分：10
學分上限：25
```

uv run python TestDriver.py

### F2 測試情境（[`test_f2.py`](../../TestDriver/test_f2.py)）

| 情境 | 預期結果 |
| :--- | :--- |
| 新課程與已選課程、教室皆不衝突 | 通過 |
| 教室衝堂、課程衝堂、額滿、學分超過同時發生 | 五項全部列出，時段衝突依星期、節次排序，限制排最後 |
| 同一天第 9 節與第 `a` 節都衝堂 | 第 9 節排在第 `a` 節之前 |
| 已報名活動與新課程撞時段；新報名活動與已選課程撞時段 | 都回報 `ACTIVITY_CONFLICT` |
| 重複加選 | `ALREADY_ENROLLED`，不誤報為衝堂 |
| 學號或課程不存在 | `NOT_FOUND` |
| 修改課程時檢查教室 | 排除課程本身 |
| 加選成功 | 學生清單與課程人數一起更新 |
| 加選有衝突 | 資料完全不變 |
| 退選；再退選一次；退選不存在的課 | 人數減 1；`NOT_ENROLLED`；`NOT_FOUND` |

### 本迭代尚未完成事項

### 本迭代遇到的問題

1. 系統改版與測試搬移未經 Pull Request，造成 22 個測試失敗、CLI 測試縮減等問題較晚才被發現。

3. F4 依本迭代的介面設計先寫測試再實作，並補齊 10 項活動資料。
4. 整理 F6 的測試總表，確認正常、邊界、錯誤及衝突案例各至少 10 個。
