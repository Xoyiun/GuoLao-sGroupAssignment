## 一、本週系統版本（可執行 v2）

程式位於 [`CampusPlanner/Code/`](../../CampusPlanner/Code/)，資料位於 [`CampusPlanner/UserData/`](../../CampusPlanner/UserData/)。

```text
uv run python CampusPlanner/Code/Main.py     # 執行命令列系統（在專案根目錄）
uv run pytest -q                             # 執行全部自動化測試
```

| 模組 | 檔案 | 對應功能 |
| :--- | :--- | :--- |
| 命令列介面 | `Main.py` | 選單、輸入解析、結果顯示 |
| 資料管理 | `CourseDataManager.py` | F1 課程、學生、教室的新增／修改／刪除／查詢 |
| 資料存取 | `StorageManager.py` | F6 依 ID 分檔讀寫、容錯載入 |
| 衝堂與選課檢查 | `ConflictChecker.py` | F2 |
| 課表與空閒時段 | `Timetable.py` | F3 |
| 活動與教室配置 | `VenueManager.py` | F4 |
| 共用 | `Constants.py`、`TimeSlotUtils.py` | 錯誤碼、規格常數、時段比對 |

本版 CLI 選單仍只有 F1 的 11 項功能；F2、F3 已有可獨立測試的函式，尚未接上選單（見第八節）。

## 四、自動化測試程式與結果

測試位於 [`CampusPlanner/TestDriver/`](../../CampusPlanner/TestDriver/)，每個測試都把 `TestInput` 複製到暫存資料夾後再操作，不會改動原始測試資料。

```text
uv run pytest -q
129 passed
```

| 分類（pytest 標記） | 數量 | 說明 |
| :--- | ---: | :--- |
| normal | 10 | F1 正常案例 |
| boundary | 11 | F1 邊界案例 |
| error | 10 | F1 錯誤案例 |
| extra | 38 | 參數化與較細的檢查 |
| persistence | 16 | F6 分檔存取與容錯載入 |
| acceptance | 5 | 資料量、測試資料格式、測試資料不得有教室撞期 |
| cli | 31 | 命令列介面 |
| f2 | 8 | F2 衝堂與選課檢查 |
| **合計** | **129** | |

### F2 測試案例（[`test_f2.py`](../../CampusPlanner/TestDriver/test_f2.py)）

| 測試 | 情境 | 預期結果 |
| :--- | :--- | :--- |
| `test_NoConflictPasses` | 新課程與已選課程、教室都不衝突 | `(True, OK, [])` |
| `test_AllConflictsListedAndSortedByDayAndPeriod` | 教室衝堂、兩門課衝堂、額滿、學分超過同時發生 | 五項全部列出；時段衝突依星期、節次排序，額滿與學分排最後 |
| `test_PeriodsLettersSortAfterNine` | 同一天第 9 節與第 a 節都衝堂 | 第 9 節排在第 a 節前面 |
| `test_ActivityOnDateConflictsWithWeeklyCourse` | 學生報名的活動（日期時段）落在新課程的同一星期、同一節 | `ACTIVITY_CONFLICT` |
| `test_AlreadyEnrolledIsRejected` | 加選已經選過的課 | `ALREADY_ENROLLED`，不誤報為衝堂 |
| `test_UnknownStudentOrCourse`（2 項） | 學號或課程代號不存在 | `NOT_FOUND`，並標明是學生或課程 |
| `test_ClassroomConflictIgnoresTheCourseItself` | 修改課程時檢查教室，排除課程本身 | 排除自己時不衝突，不排除時回報 `ROOM_CONFLICT` |

F3 目前沒有自動化測試，作業要求的「連續三節空堂、跨日查詢、同一天多門課程」三種情境尚待補上。

## 八、Iteration Review 2

**完成什麼**
1. F2 衝堂與選課檢查完成並通過測試：五項限制一次全部列出，依星期與節次排序。
2. 資料儲存統一為依 ID 分檔，刪除舊格式；單一資料檔損毀時略過並備份，不影響其他資料。
3. 修正 9 個缺陷（D03–D09），自動化測試由 112 項增加為 129 項，全部通過。

**未完成什麼**
1. F2 尚未接上 CLI，也還沒有實際執行加選、退選並同步更新人數的函式。
2. F3 缺少依星期／節次／課程代號查詢與統計功能，也尚無自動化測試。
3. F4 的需求分析與介面設計文件尚未撰寫。
4. 分支 `C` 本週的修改尚未推送與開 Pull Request。

**遇到什麼問題**
1. 系統改版未經 Pull Request 與測試就提交，造成 22 個測試出錯而未被發現。
2. F2、F3 初版程式由組長撰寫，與工作分解表的負責人（F2：C、F3／F4：D）不同，負責人需要先讀懂他人的程式。
3. 測試資料從迭代 0 就有教室撞期，直到 F2 補上教室檢查才被發現。

**下一個迭代如何改善**
1. 所有修改都經 Pull Request，並在測試全部通過後才合併。
2. F3、F4 交回工作分解表的負責人，並先補上 F3 驗收要求的三種測試情境。
3. 在 CLI 加入加選流程；F1 新增、修改課程時呼叫 F2 的教室衝堂檢查（D11）。
